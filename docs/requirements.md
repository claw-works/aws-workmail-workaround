# 需求文档 — SES 邮件接收转发系统

## 1. 项目目标

替代即将下线的 AWS WorkMail,实现域名邮件的**接收、归档、按规则转发**。

## 2. 基本参数(已确认)

| 参数 | 值 |
|---|---|
| 测试域名 | `brclient.chat`(已在 Route 53) |
| Region | `us-west-2` |
| MX | `brclient.chat. MX 10 inbound-smtp.us-west-2.amazonaws.com.` |
| From | `brclient.chat` 域名地址(如 `noreply@brclient.chat`) |
| 兜底邮箱 | 一个默认邮箱(地址待填),所有邮件都转到这里 |
| IaC | CloudFormation |

## 3. 功能需求

### FR-1 邮件接收
- 接收发往 `brclient.chat` 指定地址的邮件(如 `support@`)
- SES Email Receiving 接入,MX 指向 `inbound-smtp.us-west-2.amazonaws.com`

### FR-2 邮件归档
- 每封邮件以完整 MIME 存入 S3
- 支持生命周期策略(保留期限待定)

### FR-3 全量转发到默认邮箱(v1,已确认)
- 收到邮件后触发 Lambda,**所有邮件一律转发到默认邮箱**
- 默认邮箱 = **全量归口**,是本期唯一的转发目标
- 本期**不做**收件地址路由,**不做** AI 内容分类(留待后续版本叠加)
- 转发时:
  - `From` 改为 `brclient.chat` 验证地址
  - `Reply-To` 保留原始发件人
  - 保留原始正文、附件、格式

## 4. 非功能需求

| 项 | 要求 |
|---|---|
| 可靠性 | 邮件不丢失;转发失败要有重试/告警,原始邮件已在 S3 可追溯 |
| 可观测性 | Lambda 日志入 CloudWatch;转发成功/失败可查;AI 决策结果记录 |
| 安全 | S3 桶策略最小权限;Lambda 角色最小权限;桶默认加密 |
| 成本 | 归档用生命周期策略;AI 调用按量,注意每封邮件一次推理的成本 |
| 可维护 | 地址路由规则集中配置;AI 提示词/类别可调整 |

## 5. 明确不做(Out of Scope)

- ❌ IMAP/POP 客户端收发
- ❌ Webmail 界面
- ❌ 日历、联系人、用户邮箱管理
- ❌ 主动发送营销/通知邮件(转发除外)
- ❌ SNS / IM 通知通道(本期不做)

## 6. 约束与风险

| 项 | 说明 | 应对 |
|---|---|---|
| SES 沙盒 | 默认每天 200 封、仅发验证地址 | 转发到外部邮箱前申请移出沙盒 |
| Region | us-west-2,MX 必须对齐 | 部署前核对 MX |
| SPF/DKIM | 直接重发原邮件会校验失败 | From 换本域名,Reply-To 保留原发件人 |
| 域名验证 | 未验证无法接收 | 部署前完成 SES 域名验证 |
| AI 路由准确性 | 内容分类可能误判 | 有明确类别定义 + 默认兜底;记录决策便于回溯 |
| AI 成本/延迟 | 每封邮件一次推理 | 简单邮件可先走地址规则,AI 仅在需要时调用 |
